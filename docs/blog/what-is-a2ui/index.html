What is A2UI? Google's A2UI 1.0, explained

A2UI 1.0 is Google's stable open protocol for agents that answer with native screens. What it is, what 1.0 adds, and how it fits MCP Apps and AG-UI.

MD Chaitanya Giri · Nov 12, 2026 · 5 min read Concepts

A2UI is Google’s open protocol that lets an AI agent answer with an interactive screen, such as a form or a chart, which your app draws with its own components. Google released A2UI 1.0, which it calls “the first stable version”, on 11 Nov 2026. Checked 12 Nov 2026.

A2UI screens can also run inside MCP Apps, so if MCP is new to you, start with what is an MCP server. If you run several agents at once, our Herdr alternatives guide compares tools that run them side by side. More explainers live under Concepts.

What is A2UI? #

A2UI is a protocol plus a set of libraries that let an agent send a user interface as data instead of a reply in text. Google’s announcement sums it up: “the agent describes what to show, and every app draws the UI with its own native components.” The problem it targets, in the same post, is the agent reply that arrives as “a wall of text, a poor way to compare three products or edit and approve a detailed plan.”

The A2UI README expands the name as “Agent-to-User Interface” and calls it “an open-source generative UI framework”, with a streaming protocol, “native renderers for web and mobile frameworks, and agent SDKs in several popular languages.”

The old address, github.com/google/A2UI, now leads to a2ui-project/a2ui. The GitHub API listed the Apache License 2.0, a creation date of 24 Sep 2025 and 17,124 stars at 07:35 UTC on 12 Nov 2026. Its releases had no release or tag named 1.0 when we read them; the newest was A2UI CLI v0.3.0, published 11 Nov 2026.

What is new in A2UI 1.0? #

A stable protocol with function calls in both directions, renderer libraries for major platforms, and new agent SDKs. From Google’s post:

  • Bidirectional function calls, “so a flight or reservation picker can check availability on the spot”.
  • Support for accessibility, and extensions “for any additional metadata”.
  • Renderers for React, Angular and Lit on the web, Flutter on mobile, web and desktop, and “SwiftUI on iOS and Jetpack Compose on Android (currently v0.9.1, and v1.0 coming soon)”. Further down, the post says “The Jetpack Compose renderer supports 0.9.1 today, with 1.0 coming soon.”
  • “New SDKs for TypeScript and Dart along with Python”.
  • Swappable inference formats that “reduce latency”, and in Python, A2UI Macros, which “add programmatic component expansion and data binding”.

The 1.0 specification gives its status as “Current”. It names the new messages callRendererFunction, callAgentFunction, rendererFunctionResponse and agentFunctionResponse, and it removes theme colours from the protocol so styling comes from the target framework’s native theme.

How does A2UI work? #

The agent streams JSON messages that describe a screen, and a renderer in your app turns them into native widgets. The spec says “Communication occurs via a stream of JSON objects” and defines four agent to renderer message types: createSurface, updateComponents, updateDataModel and deleteSurface. Components arrive as a flat list linked by ID, and data arrives on its own, so the agent can change content “without resending the entire component structure.”

The README splits the stack into three layers. In inference, a model guided by an A2UI skill describes the UI. In transport, an agent SDK validates that output and turns it into protocol messages. In rendering, a core library, a framework adapter and a widget catalog draw it.

The agent can only use what you allow. Google’s post says agents “place and configure only the components you register”, and the README says A2UI “expresses UI using data, not code”, checked against a schema. Google also claims A2UI binds data on the server, “so sensitive values never reach the model.”

A2UI vs MCP Apps and AG-UI #

Google’s post says A2UI and MCP Apps “work together”, and AG-UI’s introduction says A2UI and AG-UI “work well together”. Facts checked on 12 Nov 2026:

Name What it is, in its own words Who runs it Licence
A2UI “our open protocol for generative UI” Google; code at a2ui-project/a2ui Apache License 2.0
MCP Apps “Interactive UI applications that render inside MCP hosts like Claude Desktop” The MCP project, repo modelcontextprotocol/ext-apps Moving from MIT to Apache 2.0, per its LICENSE file
AG-UI “an open, lightweight, event-based protocol” for connecting agents to apps ag-ui-protocol on GitHub MIT

The MCP Apps overview says servers return “interactive HTML interfaces” that run “in a sandboxed iframe controlled by the host.” Google’s post says A2UI’s web and Flutter renderers “also work inside MCP Apps, so A2UI screens can appear in AI assistants that support MCP Apps, such as Claude and Gemini.” It adds that Alation already uses both to show its A2UI feeds in Claude. Our post on Claude’s 10 Nov tools covers interactive tools in Claude that run on MCP Apps.

AG-UI’s introduction calls A2UI “a generative UI specification” for delivering UI widgets, and AG-UI the protocol “which connects an agentic frontend to any agentic backend”. It says the two “are quite different and work well together”.

Who is building with A2UI? #

Google names Atlassian, Alation, Bloomberg and ByteDance as “already building with it”. That is Google’s claim, and the post gives these details:

  • Atlassian is “bringing A2UI to Jira”, where an agent asks the team for a missing detail with “an interactive card in the work item”.
  • Alation’s AIOS builds its feeds with A2UI, and the post shows the same feed in Claude and in Alation.
  • ByteDance released an A2UI renderer for Lynx in June 2026, and “Lynx supports A2UI 0.9 today and is adapting to 1.0”.
  • Inside Google, Gemini Notebook answers with A2UI cards, and Gemini “supports A2UI 0.9.1 today”.

Bloomberg is named with no further detail.

Where does a team of agents fit in? #

FAQ

Is A2UI open source?

Yes. The GitHub API lists the a2ui-project/a2ui repo under the Apache License 2.0, checked 12 Nov 2026. Google's 11 Nov 2026 post calls its renderer SDKs "open-source".

Is A2UI the same as AG-UI?

No. AG-UI's introduction describes A2UI as "a generative UI specification" and AG-UI as the protocol "which connects an agentic frontend to any agentic backend". The same page says the two "are quite different and work well together".

Does A2UI work in Claude?

Google's post says the web and Flutter renderers work inside MCP Apps, "so A2UI screens can appear in AI assistants that support MCP Apps, such as Claude and Gemini." It also says Alation already shows its A2UI feeds in Claude.

Which platforms does A2UI render on?

Per Google's 11 Nov 2026 post: React, Angular and Lit on the web, Flutter on mobile, web and desktop, and SwiftUI on iOS and Jetpack Compose on Android, which the post marks "currently v0.9.1, and v1.0 coming soon".

How do I move from A2UI 0.9 to 1.0?

Google points 0.9 users to an evolution guide that "covers every change". The 1.0 specification lists renamed wire envelopes, bindings prefixed with @ and new function call messages among the differences.
