Black October: What PHP2Shell Is and How to Patch (Oct 2026)

Black October is the scramble around PHP2Shell, two critical PHP flaws fixed on 21 Oct 2026. Who found them, the fixed versions and how to patch.

MD Chaitanya Giri · Oct 23, 2026 · 5 min read News

Black October is the name some security people gave this month’s run of hacks, bugs and emergency patches, with PHP2Shell at its centre: two critical flaws in PHP itself, CVE-2026-109618 and CVE-2026-109619, fixed on 21 Oct 2026. If you run PHP, update to 8.5.12, 8.4.27, 8.3.36 or 8.2.35. Checked 23 Oct 2026.

Every source below was checked on 23 Oct 2026. We first flagged the story in our 22 Oct brief.

What is Black October? #

It is a nickname for a bad few weeks, not one bug. Axios (we read its Yahoo copy) reported on 22 Oct that cyber pros use the name “due to the sheer volume and the level of risk.” 404 Media wrote the same day that infosec experts took it up after PHP2Shell, alongside incidents at GitLab, Plex, Railway and OpenCode. Axios added that many organisations had so far avoided massive real world harm.

What is PHP2Shell, in plain words? #

PHP2Shell is two memory bugs in the PHP engine that can let an attacker run code on a server without logging in. The php.net advisory explains both. If a request hits PHP’s memory limit, or another fatal error, at the wrong moment, PHP can leave half built data or a pointer to freed memory behind. The cleanup step, or the next request on the same worker, then trusts it.

Both rate 9.2 on CVSS v4.0. Because the bug is in PHP, not the app, Wiz says even a “Hello World” page can be vulnerable; it ran code on the latest WordPress, Drupal and Joomla container images. php.net puts mod_php at highest risk, with PHP-FPM, php-cgi, FrankenPHP and LiteSpeed also exposed.

Who found it, and what did AI do? #

Several teams, close together. The PHP Foundation says a PHP core developer spotted signs of the memory problem in 2024, but no exploit path turned up and the fix stalled. Calif began auditing PHP on 30 Jul 2026 under OpenAI’s Patch the Planet program and reported remote code execution on 11 Aug; OpenAI independently reported the same root cause. Wiz added attack vectors on 24 Aug.

Wiz says it used Gemini 4 Argon and GPT-5.6 Sol, and that frontier models made the exploit chain practical. Calif’s write up describes its agent tracing the bug through PHP’s source. OpenAI, quoted by Axios: “To our knowledge, frontier AI found these vulnerabilities before attackers did.” Our view: AI shortened the road from a known weak spot to a working exploit. People had noticed the weak spot two years earlier.

Which PHP versions are affected and fixed? #

Every supported branch got a fix on 21 Oct 2026. Wiz and Cloudflare say the flaws reach back to PHP 5.4. Our selection of rows from the php.net advisory and release notes:

Branch Fixed release, 21 Oct 2026 Note from php.net
8.5 8.5.12
8.4 8.4.27
8.3 8.3.36
8.2 8.2.35 End of life 31 Dec 2026
8.1, 8.0, 7.4 None Source backports only; ask your vendor
Older None Upgrade

How did governments and sites respond? #

Fast, and often by switching things off. The PHP Foundation says the CVE ids leaked on 20 Oct with a wrong score of 10.0, so the release moved up a day to 21 Oct, 14:00 UTC. It says Chainguard broke the embargo by publishing patched images more than six hours early.

Axios reports the NSA told operators to take sites down if they could not patch in time, and the UK’s NCSC gave similar advice. Wikimedia took its Cloud Services offline on 20 Oct as a precaution. 404 Media says 4chan and Archive.org went down briefly too, and Axios counted dozens of sites in the US, UK and elsewhere.

Is anyone exploiting PHP2Shell? #

Attempts, yes. Confirmed breaches, not in any source we read. Cloudflare’s CEO Matthew Prince posted, per 404 Media, that Cloudflare saw thousands of attempts in the 10 hours before the announcement, tens of thousands in the 45 minutes after, hundreds of thousands within 2 hours, then millions. AWS logged a honeypot attempt on 17 Oct, four days early. The PHP Foundation’s executive director told Wired there had been “no successful attempt at remote code execution” to its knowledge.

Do the public exploits even work? #

Many do not, says the loudest dissent. Elias Taylor wrote on 21 Oct that public proofs of concept “do not work against a vanilla PHP instance”, and that many need an existing file inclusion hole. PHP’s security team also found no working one at release. Taylor still says patch.

The other side: Wiz and Calif showed their own exploits on stock setups, and Trail of Bits’ CEO posted that his firm built one in a day with Codex, 404 Media reported. Our view: a broken script on GitHub is no reason to wait.

What should you do now? #

Update PHP today, then check you were not hit first.

  1. Run php -v on servers you manage. In WordPress, look under Tools > Site Health > Info > Server, as the WordPress project says.
  2. Update to the fixed release for your branch. php.net says distributions and LTS vendors got the patch early, so check your vendor’s packages, then restart PHP.
  3. On managed hosting, ask your host. Cloudflare says updating site code or plugins alone does not fix this; WordPress plans no update.
  4. On 8.1 or older, upgrade. WordPress says that if you manage your own hosting, consider taking the server offline until you can; the NCSC says the same for any system you cannot patch or mitigate in time.
  5. Cannot patch today? php.net lists interim settings such as memory_limit=-1 and session.upload_progress.enabled=0, which reduce exposure but do not make you safe.
  6. Cloudflare’s WAF rules have protected free and paid WAF users by default since 03:02 UTC on 21 Oct; paid plans should check the Managed Ruleset is in block mode. Keep them on while you patch, not instead.
  7. Look back from at least 17 Oct, as AWS advises. Wiz lists signs: odd multipart requests followed by memory limit errors or repeated HTTP 500s, and malformed PHPSESSID cookies.

FAQ

Which PHP version fixes PHP2Shell?

PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35, all released on 21 Oct 2026, according to php.net. PHP 8.1 and older get no release from the PHP project; some distributions and long term support vendors backport the fix.

Is my WordPress site affected by PHP2Shell?

It can be, because the flaws are in PHP itself, not in WordPress. The WordPress project said on 21 Oct 2026 that no WordPress update is required or planned, and that you can see your PHP version under Tools > Site Health > Info > Server.

Did AI find PHP2Shell?

AI helped. The PHP Foundation says Calif reported the root cause on 11 Aug 2026, OpenAI reported it independently, and Wiz added attack vectors on 24 Aug. Wiz says frontier models made building the exploit practical. A PHP core developer first spotted signs of the problem in 2024.

Is PHP2Shell being exploited?

Attempts are widespread. Cloudflare's CEO reported millions of attempts, and AWS saw one as early as 17 Oct 2026. The PHP Foundation told Wired that, to its knowledge, no attempt at remote code execution had succeeded.

Why is it called Black October?

Axios reported on 22 Oct 2026 that security professionals were calling the recent series of attacks Black October because of their volume and risk. PHP2Shell is the best known item in it, but not the only one.
